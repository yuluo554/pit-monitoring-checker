## 一、一句话架构

**一条确定性流水线**：观测文件 → 解析校验 → SQLite 三级台账 → 来源门控 → 双控判定状态机 → 时序合规检核 → 报告导出；旁挂一条**合成数据 + 真值 + 基准评测**的自证回路。任何环节都不得引入概率模型、网络或大模型（题面 01 §六.6）。

```
                    ┌──────────────── 契约层 pmc.contract ────────────────┐
                    │ 状态枚举 / 阈值来源三态 / 条款登记 / 跨模块记录 DTO │
                    └──────────────────────────────────────────────────────┘
   data/clauses          data/dict            data/rulesets
   依据登记表            监测项目字典         规则集（阈值 null）
        │                    │                     │
        └──────────┬─────────┴──────────────┬──────┘
                   ▼                        ▼
  CSV/XLSX ──► pmc.ingest ──► pmc.db ──► pmc.rules.gate ──► pmc.alarm ──► pmc.compliance
                 (M1)        (M1 台账)      (门控)            (M2)          (M3)
                                                                  │            │
                        pmc.bench ◄── pmc.synth (M1 真值)         └──► pmc.report (M5 xlsx)
                          (M4)                                            │
                                                    pmc.gui (M5，只消费 CLI/引擎 API)
```

## 二、技术选型与弃选项

| 面 | 选定 | 弃选与理由 |
|---|---|---|
| 语言/底线 | Python ≥ 3.8，3.8 与 3.12 双端同一断言 | 不追新语法：基准要在"明确依赖清单 + 纯标准库"的干净环境一键复现（题面 01 §模块 5 纪律） |
| 内核依赖 | **零第三方依赖**（`dependencies = []`） | 弃 pandas/numpy：本工具的判定是"比较 + 状态迁移 + 时序检核"，没有向量化需求；引入它们会让"干净环境复现"多两个失败面 |
| 存储 | 标准库 `sqlite3`，单文件台账 | 弃 JSON 文件库：报警闭环、修订链、追溯清单都要跨轮次关系查询与唯一约束；弃 Postgres/DuckDB：免安装桌面工具不能要求用户起服务 |
| 输入解析 | CSV 用标准库 `csv`；XLSX 用 `zipfile` + `ElementTree` 读 sheet XML | 弃 openpyxl 作为必读路径：导入通路不能因为一个第三方包版本变化就断；openpyxl 只在需要写复杂样式时再评估（当前无需求） |
| 报告输出 | **xlsx：标准库直写 OOXML**（`zipfile` + 固定 `ZipInfo`），含原生过程线图 | 弃 openpyxl：它写入真实创建时间与作者字段，破坏"两次导出逐字节一致"与身份纪律；弃 docx：题面要求过程线图，docx 内嵌图表比 xlsx 原生 chart 麻烦得多；弃 pdf：不是可编辑格式 |
| 判定引擎 | 规则优先状态机（纯 Python） | 弃概率判定与 LLM 兜底：题面 §模块 2 "不做概率判定"、§六.6 "任何顺手加个 LLM 问答都不进主线" |
| 界面 | PySide6 多页签 + onedir exe（M5） | 弃 Web 面板：受众在项目部与监理办，桌面双击比"起服务开浏览器"更贴近现场；同一内核保留 CLI 通路，Linux/命令行使用说明与 exe 同源 |
| 打包 | PyInstaller onedir 双 exe（GUI + CLI 控制台） | 弃 onefile：内嵌台账数据与白名单审计在 onedir 下可逐份对账 |
| 随机数 | 自研 splitmix64（`pmc.synth.rng`） | 弃 `stdlib random`：不承诺跨解释器版本序列一致，会打挂"逐字节复现" |

## 三、分层禁令（`tests/test_layering.py` 实跑断言）

层：`contract → db / catalog / rules → ingest → alarm → compliance → report → bench → gui`（`synth` 与 `ingest` 平行，只依赖 contract）。

- `contract` 是最底层，**不得反向依赖任何业务层**；状态与阈值语义只在这一层定义，GUI/报告不得另立一套；
- `rules` / `db` / `catalog` 不得依赖 `alarm` / `compliance` / `report` / `gui`；
- 只有 `gui` 层允许 `import PySide6`，且必须留在函数体内的惰性分支（无 extras 环境仍可 `import pmc.gui.app`）；
- 内核任何模块不得 `import socket/urllib/http/requests/random`（全离线 + 确定性两条红线，各一条测试）。

**为什么用行为断言而不是 import 检查**：跨层禁令的意图是"判定不读界面、内核不联网"。AST 的 import 扫描足够覆盖这两条，因为它扫的是全部源文件；而"判定层不许 import `re`"这类越界表述会在复用工具函数时误伤真实依赖——本题不做这种跳层禁令。

## 四、单一事实源与降级策略

1. **CLI 是唯一的对外行为入口**：`pmc` 的每个子命令就是一条端到端能力；GUI 只调用 CLI/引擎函数，不复制判定逻辑。
2. **退出码语义**（M0 定稿，`tests/test_cli_surface.py` 锁定）：

   | 码 | 含义 | 场景 |
   |---|---|---|
   | 0 | 完成 | 结果可直接使用 |
   | 1 | 完成但有降级 | 存在未闭环报警 / 存在未核对依据 / 部分规则不启用 |
   | 2 | 输入不可用 | 缺文件、编码错、单位不一致、契约校验失败、argparse 参数错误 |
   | 3 | 未实现 | 命令所属里程碑未到（骨架期占位，M5 后本档可删） |

   占位命令返回 3 而不是 0 —— "未实现"不得伪装成成功，这是 M0 唯一一条关于诚实的退出码纪律。
3. **缺依赖降级**：可选能力（GUI）缺失时抛带安装提示的异常，由 CLI 捕获后打印说明并返回 2/3，不崩溃、不静默。
4. **无网络降级**：不存在网络通路，因此也不存在"网络不可达时降级"的分支。

## 五、可复现性架构（基准的根）

| 机制 | 落点 | 守门 |
|---|---|---|
| 确定性 RNG | `pmc/synth/rng.py`（splitmix64，stream 派生） | `test_rng_determinism.py`：同 seed 同流同序列、异流隔离 |
| 禁 stdlib random / 禁时钟 | AST 扫描全部 src | 同上文件两条断言 |
| 落盘产物无时间戳 | 合成数据、真值、golden、xlsx 报告（固定 `ZipInfo`） | M1 起：两次生成逐字节一致 + EOL 守门 |
| EOL | `.gitattributes` `* text=auto eol=lf` | `test_eol_guard.py` 遍历工作树拒绝 CR |
| 干净环境 | CI 四矩阵（ubuntu/windows × 3.8/3.12） | `test_ci_workflow.py` 保证 workflow 可解析、矩阵覆盖 gui、退出码不被管道吃掉 |
| 指标四态 | `pmc.bench`（M4） | README 指标表 + `test_readme_honesty.py` 逐行对账 |

## 六、扩展位（首期不做，但不得挡路）

- 自动化监测设备接入：`pmc.ingest` 的输入适配器位（同一 `Observation` 契约即可复用）；
- 测斜剖面解释 / 稳定性验算：**独立产品线**，本题只留 `point.item_code` 与条款登记，不预留任何验算入口；
- 多基坑对比与大屏：`pmc.report` 的渲染器位；
- 若将来需要 LLM 行文润色：只允许出现在报告文字层，且判定结果对象必须由规则层产出（题面 §六.6 优先，默认不做）。
