> 版本：v2（v1 于 2026-10-07 M0 定稿；v2 为 M1 落地修订——真值 7 列、导入原因码 11 个、M1 三条命令转"已可用"）
> 本文件描述**接口契约**：五模块各自的输入/输出对象、状态语义、表结构与命令面。
> M0 已落地的契约文件在每节末标注"实现在"；未落地的算法标里程碑号。

## 0. 契约总则（三条硬纪律）

| # | 纪律 | 落地点（不是文档承诺） |
|---|---|---|
| R1 | 未挂来源或未核对的阈值不得生效 | `Threshold.disabled_reason()`；`rules/gate.py` 单点决定启用；SQLite `alarm_state` 的 CHECK 拒绝"无来源却出结论" |
| R2 | 待定值结果对象的阈值数值字段必须为空 | `Threshold.blank_output()`；`AlarmRecord.validate()` 抛 `ContractError`；DDL CHECK 拒绝 `state='undetermined'` 却带 `cum_threshold` |
| R3 | 判定/违规必须挂条款号，条款必须挂渠道 | `clause_ids` 列 + `standard_value` 的 CHECK；`data/clauses/register.json` 缺渠道即装载失败 |

## 1. 状态与阈值语义（`pmc.contract`）

### 1.1 状态集合（模块 2 输出，题面 01 §模块 2）

```
normal | prewarning | alarm | alarm_confirmed | alarm_handled | undetermined
```

- `undetermined`（待定值）：**不是"正常"的别名**。界面与报告必须单独成列，不得渲染成绿勾（`test_readme_honesty.py` 防的是同一件事）。
- 未闭环集合 `UNCLOSED_STATES = {alarm, alarm_confirmed}`：本轮数值回落也不改变"未闭环"事实，必须跨轮次延续 → 落库列 `alarm_state.unclosed`。
- 迁移表 `ALLOWED_TRANSITIONS`：未列出的迁移视为非法（引擎报错，不静默纠正）。已处置不得回退成"已确认"。
- 触发依据与状态正交：`cumulative | rate | both | none`；`undetermined` 只能配 `none`。

### 1.2 阈值双轴登记

| 轴 | 取值 | 说明 |
|---|---|---|
| 来源 `kind` | `design_value` / `standard_value` / `user_input` / `none` | 题面要求的"三选一"；`none` 即无来源 |
| 查证 `status` | `pending` / `located` / `verified` | `located` = 条号表号已定位、数值未取到，**与 pending 一样不得供货** |

`evidence` 的含义随来源变化，三者都必填：设计文件号 / 条款登记键 / 录入登记（谁、何时）。
`standard_value` 额外要求 `clause_id` + `channel` + `url` + `verified_on` 四件套齐备。

不启用原因码（核对队列的分组键）：`no_source`、`source_not_confirmed`、`located_value_missing`、`value_missing`、`unit_missing`、`evidence_missing`、`clause_id_missing`、`window_unconfigured`、`clause_not_verified`。
**"解析能力欠缺"与"等核对"必须分开统计**：前者是代码缺陷，后者是进度信息，混在一起核对队列就失去优先级。

实现在：`src/pmc/contract/status.py`、`thresholds.py`、`clauses.py`、`records.py`。

## 2. 台账结构（模块 1，`pmc.db.schema`）

11 张表，M0 已可建库并全绿：

| 表 | 作用 | 关键约束 |
|---|---|---|
| `meta` | schema 版本等键值 | 版本不符直接 `ContractError`，不迁移旧库（口径见 D21） |
| `project` | 工程/基坑基本信息 | `code` 唯一；`synthetic` 标记演示库 |
| `working_condition` | 支护型式与开挖工况时间线 | `effective_from` 支撑"工况变更即刻生效新频率"（模块 3） |
| `point` | 测点档案 + 设计报警值 + 来源三态 | `UNIQUE(project_id, code)`；`threshold_source_kind`/`threshold_status` CHECK 限定枚举 |
| `obs_round` | 轮次 | `UNIQUE(project_id, round_index)`、`round_index >= 1`；`is_intensified` 标记加密观测轮次 |
| `import_batch` | 导入回执 | `CHECK(rows_accepted + rows_rejected = rows_total)` —— 回执不平就写不进库 |
| `observation` | 观测读数 + 修订链 | `UNIQUE(point_id, round_id, revision_seq)`；`missing` 与 `value_cum` 互斥（不许插值）；`superseded_by` 指向后到记录 |
| `alarm_state` | 模块 2 判定输出 | 三条 CHECK 落实 R1/R2/R3；`UNIQUE(point_id, round_id, item_code)`；`unclosed`、`first_alarm_round_id` |
| `disposition` | 确认/处置/加密观测记录 | `handle` 必须有 `actor_role`（签字栏空白不得声称已审核） |
| `violation` | 模块 3 违规清单 | `clause_ids NOT NULL`；`kind ∈ missed/over_interval/stale_frequency/no_intensified_after_alarm` |
| `ruleset_applied` | 哪一版规则集产出了这批结论 | `(code, version)` 主键 + sha256，报告数据版本指纹的一部分 |

### 2.1 重复上报的修订链（题面 §模块 1 要点）

后到记录**不覆盖**前一条：插入 `revision_seq = max+1`，并把前一条的 `superseded_by` 指向新行。
判定引擎只取"链上最新未被 supersede 的行"，但历史完整可查 —— 这是"数据可追溯"与 Excel 重算的根本差别。

### 2.2 导入回执（`ImportReceipt`）

`rows_total = rows_accepted + rows_rejected` 且 `len(rejections) == rows_rejected`；
每条拒绝带 `source_row`（CSV 物理行号，表头算第 1 行）+ `reason_code`。

行级原因码 M1 定稿为 11 个（触发条件与优先级见 `07 §八`，断言在 `tests/test_ingest_csv.py`）：
`name_rule_violation`、`unknown_item`、`unknown_point`、`point_item_mismatch`、`unit_mismatch`、
`round_mismatch`、`bad_date`、`bad_number`、`missing_flag_conflict`、`round_not_monotonic`、`duplicate_identical`。
结构坏到无法逐行判断的（编码/BOM/表头/列数/多日期/无档案/同哈希文件重放）是**文件级硬失败**，退出码 2 且不写批次。

## 4. 模块 2 判定契约（M2 落地，接口先定）

```
输入：observation(链最新行) + point(设计值三态) + 门控通过的 rules(standard 回退档)
有效阈值 = 优先取 point 的 design_value；缺失时回退规则的 standard_value（回退必须写明条款号）
          两者皆缺 → 该判据 undetermined，不产出任何报警结论
输出：每个 (point, round, item) 一条 AlarmRecord：
      state, trigger_basis, cum_value/cum_threshold, rate_value/rate_threshold/window_days,
      threshold_source_kind, threshold_status, clause_ids, disabled_reasons,
      unclosed_carried, first_alarm_round_id
合成：cum 触发 或 rate 触发 → alarm；两者都未触发但达预警比例 → prewarning；
      两判据一个可判一个待定 → 按可判的那个出结论，并把待定记进 disabled_reasons（降级退出码 1）
```

速率：滑动窗口，窗口长度按监测项目配置（`window_days` + `window_source`），**窗口未配置 = 速率判据不启用**（`window_unconfigured`），不用默认 3 天冒充规范值。

> M2 落地细则（选取次序、未闭环延续的确切定义、迁移检查两道报错点、退出码触发集合、`pmc check` 输出契约）见 **`plan/09`**；实现落在 `pmc/alarm/engine.py`。

## 5. 模块 3 检核契约（M3 落地）

四类违规已进 DDL 的 `kind` 枚举：`missed` / `over_interval` / `stale_frequency`（工况变更后仍按旧频率）/ `no_intensified_after_alarm`（报警后未加密观测，读模块 2 的 `unclosed` 标记）。
每条输出 `rule_id` + `clause_ids` + `evidence_json`（间隔天数、上一轮时间、生效工况 code）。
**本模块只报"应核实"，不写"已确认违规"**（题面 §六.4）。

## 6. 模块 4 报告契约（M5 落地）

- 页眉固定免责声明（题面 §六.1）；
- 数据版本指纹 = 台账内容 sha256（`LedgerFingerprint`），规则集版本从 `ruleset_applied` 取；
- 生成时间**不写进 xlsx 的 ZIP 元数据**（固定 `ZipInfo` 日期），只在正文由用户确认填写 —— 两次导出逐字节一致才可断言；
- 追溯清单：`TraceRow(报告单元格 → 表名 + row_id + 列名)`，一个数字一行；
- 签字栏空白 = 报告标注"未审核"，`disposition` 无记录时不得出现"已处置"字样；
- 过程线图用 xlsx 原生 chart（`xl/charts` XML 直写），不生成位图 —— 保证可编辑且无字体依赖。

## 7. 模块 5 基准契约（M1 数据 / M4 评测）

真值行格式（`data/README.md` 已定，M1 落文件；列义见 `07 §6.1`）：

```
event_id, point_id, round_index, event_type, injected_magnitude, expected_first_alarm_round, also_expect
```

`event_type ∈ {step, rate_burst, drift, missing, outlier, unit_error, duplicate_report}`。
`point_id` 放的是**测点编号**（`point.code`），不是数据库自增 id —— 冻结产物不得依赖建库顺序。
M1 把 6 列扩到 7 列（新增 `also_expect`），变更见 `06 §五`：评测要按"全部非 pass 集合"对账，光有主期望会把漏报算成正确。
指标：报警召回率、误报率、首超报警轮次定位误差、漏报清单；四态口径 + 退出码 0/1/2 锁进测试。
**门槛**：召回率 ≥ 0.95 且误报 = 0（M4 定稿时可上调，不得下调）。
