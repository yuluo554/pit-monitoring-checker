# 题目：建筑基坑工程监测数据判读与预警工具

> **性质**：模拟赛题定位，不参赛 —— 目标是发 GitHub 的独立开源桌面工具题
> **目标产出**：仓库 `pit-monitoring-checker`（本地目录 `10-7-pit-monitoring-checker`），Windows 免安装桌面 exe + 全离线内核
> **版本史**：v1（2026-10-07）定稿 —— 五模块首期范围、双控阈值报警状态机、合成时序带真值基准
> **定位宣言**：它管的是一座基坑从开挖到封底的**全部量测读数**——台账持久、阈值来源可溯、"报警未处置"能一路跟着下一个轮次。大模型聊天框没有你的上一轮数据，也不会替你守住"超标未闭环不得进入下一工况"这条纪律；它做的不是"读一段文字给建议"，是**每天两百行读数里那一次真正该响的警报**。

---

## 一、介绍

### 1.1 痛点（真实、可举证）

基坑工程被纳入"危险性较大的分部分项工程"管理，施工单位须按批准的专项方案实施监测、监理单位须对监测数据进行核查，监测数据超过报警值时必须**加密观测并及时处置**。依据：

- 《建筑基坑工程监测技术标准》GB 50497-2019（编号与名称已核，见 data/README）；
- 《危险性较大的分部分项工程安全管理规定》住房城乡建设部令第 37 号（2018-06-01 施行）及其配套办公厅文件；
- 各省市住建部门的基坑监测数据报送/远程监控平台要求（⬜待逐条核对到具体文号）。

现业痛点集中在三处，且都不在"规范公式验算"这一层：

1. **数据量与轮次压垮人工**：一个基坑动辄几十个测点、每天一轮、连续数月；累计量与变化速率要双控，人工 Excel 判读会漏"速率突增但累计量未超"的报警；
2. **报警没有闭环状态**：Excel 每轮次重算，上一轮的报警是否已处置、是否已按要求加密观测，没有任何地方在记账；
3. **成果报告靠复制粘贴**：日报/周报/阶段报告的过程线与报警台账要手工拼，签字栏与数据版本对不上是常见的资料问题。

### 1.2 开源空白

GitHub 检索（2026-10-07，`gh search repos`）："foundation pit monitoring" 无结果；中文"基坑 监测"仅命中 2 个 0～1 星、非工具性质仓库（个人主页、概念 demo）。行业现状是商业监测云平台（依赖厂商硬件与网络）+ 各单位自用的 Excel 模板，**没有离线、可复现评测、判定能挂条款号的开源判读工具**。

## 二、任务要求（首期 5 个模块，其余留扩展）

> **通用确定性纪律**：凡进入计算路径、判定路径或落库的阈值/系数/条款号，必须有来源登记（设计文件值 / 标准条文值 / 用户手填值三选一）；未挂来源的一律输出"待定值"状态，**不得生效、不得进入报警判定**。

### 模块 1：监测台账与测点档案

- **输入**：工程与基坑基本信息表、支护型式与开挖工况表、测点档案（测点编号、监测项目、布设位置、起始值、设计报警值）、逐轮次观测数据（CSV / XLSX）。
- **输出**：本地 SQLite 三级台账（工程 → 测点 → 轮次），带导入回执（哪些行入库、哪些行被拒及原因）。
- **引擎**：确定性解析 + 校验。测点编号唯一性与命名规则、监测项目字典、轮次时间单调性、单位一致性、缺测标记（不许自动插值）、重复导入去重。
- **要点**：同一测点同一轮次重复上报必须可识别（后到记录进"修订链"而不是静默覆盖）。

### 模块 2：双控阈值报警判定引擎（本题核心）

- **输入**：模块 1 台账 + 阈值规则集。
- **输出**：`测点 × 轮次 × 监测项目` 的状态记录：`正常 / 预警 / 报警 / 报警已确认 / 报警已处置 / 待定值（无阈值来源）`，每条状态附触发依据（累计量、速率、二者之一或同时）与条款号。
- **引擎**：规则优先的状态机，不做概率判定。
  - 累计量判据：本次累计变化量 vs 累计控制值；
  - 速率判据：单位时间变化量（滑动窗口，窗口长度按监测项目配置） vs 速率控制值；
  - 双控合成：任一判据触发即"报警"，两者均未触发但达预警比例即"预警"；
  - 状态延续：上一轮"报警"未确认/未处置时，本轮即使回落也保持"未闭环"标记 —— 这是必须持久化才能得到的东西。
- **纪律**：阈值默认取设计文件值；无设计值时可回退到标准表格值，回退必须写明条款号；两者皆缺 → 输出"待定值"，不得凭空生成阈值。

### 模块 3：监测频率与时效合规检核

- **输入**：开挖工况时间线 + 观测轮次时间戳 + 频率规则集。
- **输出**：漏测/超间隔/工况变更后未按新频率执行/报警后未加密观测 的违规清单，逐条挂条款号。
- **引擎**：纯确定性时序检核。频率要求随开挖深度与工况变化，须支持"工况变更即刻生效新频率"。
- **要点**：这是最容易做成"看起来像报告生成器"的模块，必须给出可核验的判定，而不是文字提醒。

### 模块 4：成果报告与交付物

- **输入**：台账 + 报警状态 + 检核结果。
- **输出**：监测日报 / 周报 / 阶段报告（xlsx、docx 或 pdf，至少一种可编辑格式），含测点过程线图、报警台账页、本轮异常测点清单、签字栏位与数据版本指纹（生成时间 + 台账哈希）。
- **交付物纪律**：报告里的每个数字都能回溯到台账行（导出追溯清单）；签字栏空白不得声称"已审核"。

### 模块 5：内置基准与合成数据生成器

- **合成生成器**：按"开挖—回弹—流变"形态生成正常序列，并植入已知真值的异常事件：阶跃突变、速率突增、仪器漂移、缺测、异常跳点、单位错误、重复上报。真值 = 事件类型 + 发生轮次 + **理论上首个应触发报警的轮次**。
- **评测指标**：报警召回率、误报率、首超报警轮次定位误差、漏报清单；回归用例需给出可复算的期望值。
- **纪律**：基准必须在干净环境可一键复现（纯标准库 + 明确依赖清单），不许依赖网络与外部模型。

### 明确不做（首期排除）

测斜曲线剖面解释、支撑轴力实测值反算设计承载力、基坑整体稳定性验算、降水/管线第三方专项分析、自动化监测设备接入、BIM/大屏。**稳定性验算与支护构件验算属于另一条产品线，本题只做"数据判读与预警"。**

## 六、边界与非目标

1. **辅助定位，不是决策工具**：本工具判定的是"该轮次该测点相对已挂来源的阈值是否超标"，**不判定基坑是否安全**，不替代设计、施工、监理的处置决策；报告页眉固定免责声明。
2. **不做验算**：不输出任何支护结构内力、稳定性安全系数类结论。
3. **隐私与数据红线**：全部本地存储，不联网、不上传；演示数据使用虚构工程名、假手机号段（1990 前缀类）、假图号，合成数据文件带 `SYNTHETIC` 标记与假数据说明。
4. **结论纪律**：任何"未挂原文核对"的阈值不得进入计算路径；任何异常只能报"应核实"，不得写成"已确认违规"。
5. **品牌隔离**：本项目与现场安全隐患研判、脚手架/模板支架验算、钢结构验算、结构加固验算等既有工具无任何代码或文档引用关系，互不提及对方业务。
6. **范围红线**：首期只做 5 个模块，其余全部留扩展；任何"顺手加个 LLM 问答"的改动都不进主线。
