| ID | 日期 | 议题 | 结论 | 理由与弃选项 |
|---|---|---|---|---|
| D01 | 2026-10-07 | plan 文档编号 | 按方法论规范布局：`02 架构`、`03 模块详设与接口契约`、`04 数据计划`、`05 里程碑与验收门`、`06 交付对标与决策记录`；原 `02–06` 里程碑设计文档顺延为 `07–11` | 用户指定"按 skill 的规则布局"；原编号只存在于 `00` 索引表（文件尚未创建），改索引零成本 |
| D02 | 2026-10-07 | 包名与布局 | 包名 `pmc`，src 布局，控制台脚本 `pmc`，GUI 脚本 `pmc-gui` | 与同族仓库（`sdc`）一致；`pit_monitoring_checker` 作为包名过长且导入不便 |
| D03 | 2026-10-07 | 内核依赖 | `dependencies = []`，零第三方依赖；重依赖只进 extras | 题面 §模块 5 "纯标准库 + 明确依赖清单"是硬要求；pandas/numpy 对"比较 + 状态迁移"无收益 |
| D04 | 2026-10-07 | 存储 | 标准库 `sqlite3` 单文件台账，11 张表（含修订链、状态、处置、违规、规则集版本） | 弃 JSON 文件：闭环与追溯是关系查询；弃服务端数据库：桌面免安装 |
| D05 | 2026-10-07 | 阈值登记模型 | **双轴**：来源三态（design/standard/user）× 查证三档（pending/located/verified） | 单轴会把"知道条号在哪"和"一无所知"挤成同一个值；设计值与用户手填值不属外部标准，需要各自的凭证字段 |
| D06 | 2026-10-07 | 规则文件不写 `enabled` | 启用与否由 `rules/gate.py` 单点决定，数据自称启用即 schema 报错 | 否则规则可以绕过整套核对体系 |
| D07 | 2026-10-07 | 速率窗口 | 属项目配置，出现数值必须挂 `window_source`；未配置 → 该判据按 `window_unconfigured` 不启用 | 弃"默认 3 天"：内置默认系数等于凭空生成阈值 |
| D08 | 2026-10-07 | 设计值归属 | `design_value` 只能在测点档案（`point` 表），不得写进规则集 | 设计值逐基坑不同；写进规则集会让人拿规则自称设计值 |
| D09 | 2026-10-07 | 双控合成 | 任一判据触发即 `alarm`；均未触发但达预警比例 → `prewarning`；一判据可判一判据待定 → 按可判的出结论并记原因码，退出码 1 | 题面 §模块 2 双控合成；"待定"不连坐已有判据，否则漏报率被人为抬高 |
| D10 | 2026-10-07 | 报告格式 | **xlsx，标准库直写 OOXML（固定 `ZipInfo`）**；不引入 openpyxl / python-docx；因此没有 `report` extras | 用户拍板。决定性理由是纪律而非便利：可编辑格式 + 原生过程线图 + 两次导出逐字节一致 + 不写创建时间与用户名 |
| D11 | 2026-10-07 | 退出码 | 0 完成 / 1 降级 / 2 输入不可用与契约失败与参数错误 / 3 未实现 | 占位命令返回 3，不伪装成功；argparse 自带 2 与"输入不可用"合并（与同族仓库口径一致） |
| D12 | 2026-10-07 | GUI 定位 | 只消费 CLI/引擎 API，不另起第二套行为；Qt 导入留惰性分支 | 与"CLI 单一事实源"同纪律；无 extras 环境仍可 `import pmc.gui.app` |
| D13 | 2026-10-07 | GUI/打包版本区间 | `PySide6>=6.4,<6.7`（写上界）；`pyinstaller>=6.0,<7` | 3.8.8 上 6.7+ 元数据要求 ≥3.9；重依赖在老解释器上只写下限等于没 pin |
| D14 | 2026-10-07 | pytest addopts | 不含 `-q`（只留 `-p no:cacheprovider`） | 命令行再传 `-q` 叠加成 `-qq`，`N passed` 汇总行整行消失，CI 数不出数 |
| D15 | 2026-10-07 | 依据登记与供货 | `status=verified` 才供货；`located` 与 `pending` 一样不得供货；每条必须挂渠道与检索日期 | 沿用同族仓库验证过的三档模型；搜索摘要一律不采信 |
| D16 | 2026-10-07 | EOL | `.gitattributes` `* text=auto eol=lf` + 遍历工作树拒绝 CR 的守门测试 | 本机 `core.autocrlf=true` 已实测；只有全新 clone 会暴露，故前置到 M0 |
| D17 | 2026-10-07 | CI | 四矩阵（ubuntu 3.8/3.12 + windows 3.8+gui/3.12）；step 名含冒号必须加引号；run 命令禁 `| tail`/`| head`/`PIPESTATUS` | 三条都有实测事故：非法 YAML → GitHub 不建 job；管道吃退出码 → 假绿。M0 配齐是首跑全绿的钥匙 |
| D18 | 2026-10-07 | 指标四态 | 达标 / 未达标 / 不可判（分母 0）/ 不可用（通路未通），CLI、xlsx、GUI 同一口径 | "量不了"不许挤进"达标"或"未达标" |
| D19 | 2026-10-07 | 零 LLM | 首期不接入任何大模型，也不预留问答入口 | 题面 §六.6；本题价值在"每天两百行读数里那一次真正该响的警报" |
| D20 | 2026-10-07 | pyproject 解析 | 测试用行解析器读 pyproject，不用 `tomllib` | 3.8 无 `tomllib`；若 3.12 才测则等于静默少跑 |
| D21 | 2026-10-07 | schema 迁移 | 版本不符直接报错，M6 前不写迁移器 | 无历史用户；静默改表结构比拒绝启动危险得多 |
| D22 | 2026-10-07 | 分层禁令 | 用 AST import 扫描实现分层与"内核不联网"，不做"判定层不许 import `re`"这类跳层禁令 | 静态断言会误伤真实依赖；要禁的是行为，用可执行断言表达 |
| D23 | 2026-10-07 | 本轮范围 | 只交付计划 + 契约级骨架，不进入功能实现 | 用户指令"先写好计划，部署骨架，不着急直接开始" |
