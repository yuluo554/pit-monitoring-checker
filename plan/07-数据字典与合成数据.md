## 三、测点编号命名规则与字典匹配

| 项 | 规则 | 违反时的处置 |
|---|---|---|
| 测点编号 | `^SYN-[A-Z]{2,3}-[0-9]{2}$`（前缀=监测项目，序号 01–99） | 行级拒收 `name_rule_violation` |
| 数字一律 ASCII | 编号、日期、数值的正则都用 `[0-9]` 而非 `\d` | Python 的 `\d` 认全角数字，而 `float("３.４")` 照样给 3.4 —— 那等于把抄错的读数静默洗成合法值 |
| 项目前缀 | 14 项各配 2 字母：`TH TV DH CV PB PF AF WL GD BV BT PL SH CW` | — |
| 工程编码 | `^SYN-[A-Z0-9]{2,10}$` | 建档时拒绝 |
| 字典匹配 | `item_code` 必须出现在 `data/dict/monitoring_items.json` | 行级拒收 `unknown_item` |
| 测点档案 | `point_code` 必须已在该工程档案内 | 行级拒收 `unknown_point` |
| 档案一致性 | 行内 `item_code` 必须与该测点档案的 `item_code` 相同 | 行级拒收 `point_item_mismatch` |
| 单位 | 行内 `unit` 必须等于字典单位 | 行级拒收 `unit_mismatch` |
| 同文件单位一致性 | 同一 `item_code` 在一个文件内出现多种单位 | 该单位的所有行按 `unit_mismatch` 拒收（不猜哪个对） |

## 四、形态学与量化

### 4.1 三形态（`04 §2.1` 的落地公式）

累计值 `v(r)` 定义为**相对首测读数的变化量**（单位=字典单位），可正可负，报警判据取其绝对值。

| 段 | 适用 | 每轮斜率 |
|---|---|---|
| 开挖影响段 | `morph=growth` 的项目 | `slope = base × gain(c) × Δt`，`gain(c)` 为工况增益（开挖越深越大），`Δt`=观测间隔天数 |
| 回弹段 | `morph=rebound`（立柱竖向位移、基坑底隆起） | `slope = −0.45 × base × gain(c) × Δt`，即反向缓变 |
| 流变段 | 全部，末段轮次（本站轮次的最后 25%） | `slope = 上一段斜率 × exp(−(r − r_f)/τ)`，`τ=4`，渐近收敛 |
| 季节项 | `morph=seasonal`（地下水位） | `v(r) = trend(r) + 0.12 × cum_threshold × sin(2π r / 12)`，只用轮次序，不读时钟 |

- 第 1 轮的变化量恒为 `0.0`（首次读数即基准），所以每条序列都从原点起步，回弹段才谈得上"反向"。
- `base` 由本站目标反算：`base = target_ratio × cum_threshold(item) / 本站历次天数`。
  `target_ratio`：`SYN-LJ3`=0.18、`SYN-ZHDQ`=0.62、`SYN-YYCG`=0.62。
  **这两个数是被自检逼出来的，不是拍的**：日报站只有 7 天跨度，0.25 的基线斜率再乘工况增益 1.25 与 ±15% 抖动就顶到速率档，
  "误报率的分母"会自己先报警；季节幅度 0.35 同理会让水位在头两轮跳变出速率报警。
  生成器 `check_attributable` 对任何"基线就触发"的档案直接报 `SynthError`。
- 逐轮抖动：`slope ×= rng.uniform(1−0.15, 1+0.15)`，stream 名 `morph/<site>/<point>`（每个测点独立派生，不受其他测点影响）。

### 4.2 分辨率量化与固定小数位

| 单位 | 量化分辨率 | 落盘小数位 |
|---|---|---|
| `mm` | 0.1 mm | 1 |
| `kN` | 1 kN | 0 |
| `m` | 0.01 m | 2 |
| `‰` | 0.1 ‰ | 1 |

量化在植入**之后**、反算**之前**执行；反算使用的数值 = 最终落盘文本的数值。
这条顺序是硬约束：反算若用量化前的浮点值，首超轮次会与台账里的数对不上，基准的"定位误差"就失去意义。

## 六、事件植入表与真值文件

`event_type` 仍为 7 值：`step rate_burst drift missing outlier unit_error duplicate_report`。

| 事件 | 植入方式 | 期望报警 | `also_expect` token |
|---|---|---|---|
| `step` | 第 k 轮累计值一次性增加 `magnitude`（本站单位，带符号），其后各轮保持该水位；可带**回落段** `recovery_per_round × recovery_rounds`（永久水位回撤，逐轮累加，不给下一轮留下反向跳增） | 由 §七 反算，通常 = k | `alarm_basis=` 实际判据；带回落段时加 `unclosed>=N` |
| `rate_burst` | 第 k 轮起连续 `span_rounds` 轮，每轮的**增量**各加 `per_round`（超出部分保持水位） | 通常 = k（速率判据先超） | `alarm_basis=` 实际判据 |
| `drift` | 第 k 轮起每轮增量都加 `per_round`（持续加速，水位越来越偏离基线） | **> k**：首个越过阈值的轮次，证明期望值是反算而非复制 | `alarm_basis=` 实际判据 |
| `missing` | 第 k 轮写 `missing=1`、数值列留空、`raw_text=未测` | 无 | `no_interpolation;no_row` |
| `outlier` | 第 k 轮单点粗差，幅度经生成器检查仍不越过两判据（下一轮回到基线，形成尖峰） | 无 | `no_alarm;persist_exact` |
| `unit_error` | 第 k 轮**数值照抄、单位栏填非字典单位**（`mm` 读数写进 `cm`）——这就是现场最常见的单位事故 | 无（该轮不该进台账） | `no_row;reject=unit_mismatch` |
| `duplicate_report` | 同 (point, round) 两行：先到值 = 修正值 + `first_report_delta`，第二行为修正值；**判定只认链上最新行** | 由修正值反算，通常 = 该轮 | `import_revision=2`（+ 实际 `alarm_basis=`） |

互斥坑（当场登记，生成器强制校验）：
1. 同一 `(point, round)` 不得同时植入 `missing` 与任何数值类事件；
2. 同一 `point` 的两个事件轮次相距 < 速率窗口时，后一个事件的期望轮次必须重算（否则归因不唯一）—— 生成器直接拒绝这种排布；
3. `unit_error` 与 `missing` 造成的"该轮无值"，其后一轮的速率只能取窗口内**实际存在**的读数，不得跨过空洞补值；
4. `duplicate_report` 的第二行必须与第一行数值不同：完全同值的重复行走 `duplicate_identical` 拒收，不产生空修订。

## 七、`expected_first_alarm_round` 的反算规则

对植入后的**落盘数值序列**，按夹具档位逐轮求"首个触发轮次"：

```
累计判据在轮 r 成立  ⟺  |v(r)| ≥ cum_threshold(item)
速率判据在轮 r 成立  ⟺  存在 j<r 使 t_r − t_j ≤ window_days(site)
                        且 max over j of (|v(r) − v(j)| / (t_r − t_j)) ≥ rate_threshold(item)
                        （j 只取该轮窗口内实际有读数的轮次：缺测/被拒收的轮次不参与，也不补值）
expected = min{ r : 累计判据成立 或 速率判据成立 }     不存在则留空
alarm_basis = 触发的那个判据（两者同轮成立 → both）
```

- 无事件基线序列必须处处不触发（§九 自检），否则 `expected` 无法归因于植入事件，生成器直接报错；
- 事件测点若植入**之前**已有触发轮次，同样报错（植入不可归因 = 数据作废）；
- `duplicate_report` 用链上最新（修正）值反算，`unit_error`/`missing` 不反算（期望为空）。

## 八、导入回执与 reason_code 集合（M1 定稿）

`ImportReceipt`（`03 §2.2`）字段不变：`source_file, file_sha256, rows_total, rows_accepted, rows_rejected, rejections[]`，
纪律 `rows_total = rows_accepted + rows_rejected` 且 `len(rejections) == rows_rejected` 由 DTO 与 DDL CHECK 双重把守。

行级拒绝原因码 11 个（锁进 `tests/test_ingest_csv.py`，顺序即校验优先级）：

| reason_code | 触发条件 |
|---|---|
| `name_rule_violation` | 测点编号不符合 §三 正则 |
| `unknown_item` | `item_code` 不在监测项目字典 |
| `unknown_point` | `point_code` 不在该工程测点档案 |
| `point_item_mismatch` | 行内项目与该测点档案的项目不一致 |
| `unit_mismatch` | 行内单位不等于字典单位（含留空）；同一文件同项目出现多种单位时，非字典单位的那些行全部按本码拒收，不猜哪个对 |
| `round_mismatch` | 行内 `round_index` 与命令 `--round` 不一致 |
| `bad_date` | `observed_on` 非 `YYYY-MM-DD`，或该日历日不存在（如 `2026-02-30`） |
| `bad_number` | 数值列非空但不是 ASCII 十进制：`abc`、`1.2.3`、`nan`、`inf`、全角数字、千分位写法全部拒收 |
| `missing_flag_conflict` | `missing` 非 0/1；`missing=1` 却带数值；`missing=0` 且数值与 `raw_text` 全空 |
| `round_not_monotonic` | 文件的观测日期与台账该轮记录冲突，或该轮日期与同工程相邻轮次的次序矛盾（整批按此码拒收） |
| `duplicate_identical` | 重复上报且内容与链上最新一行逐位相同（含纯文本行）——不产生空修订 |

文件级硬失败（**不是行级拒收**，直接退出码 2 且不写批次）：
编码非 UTF-8 / 带 BOM / 表头列名与契约不符（缺列、多列、改名）/ 空文件 /
数据行列数与表头不符 / 同一文件出现多个观测日期 / `--project` 或 `--round` 在台账没有档案 /
同一工程同一轮次重复导入**同一个哈希的文件**（修订必须由新文件上报，进修订链而不是重放旧文件）。

`source_row` 一律是 CSV 的物理行号（表头算第 1 行），回执与 `observation.source_row` 同一口径。

修订链（`03 §2.1` 落地）：同 `(point, round)` 的后到行**只追加**，`revision_seq = max + 1`，
并把被取代行的 `superseded_by` 指向新行；判定（M2）与 `pmc ledger` 都只认 `superseded_by IS NULL` 的行。

退出码：全部接受 `0`；有拒绝行但批次与回执完整落库 `1`（降级）；文件级硬失败 `2`。

## 九、生成器自检断言（每次生成都跑，不过就拒绝落盘）

1. 无事件测点的全序列在任何轮次都不触发两判据；
2. 每个事件的 `expected_first_alarm_round` 存在时，其植入轮次之前的任何轮次都不触发；
3. 每座基坑 CSV 行数 = `测点数 × 轮次`；真值行数 = 植入事件数；
4. 真值里的 `(point_id, round_index)` 必须指向 CSV 中真实存在的行；
5. 事件互斥与归因唯一性（§六 四条坑）；
6. 所有落盘数值 = 按 §4.2 量化后的值（无额外小数位）；
7. 产物文本不含 CR；不含任何 `data/rulesets` 里未核对的阈值数值。

## 十、产物布局与冻结纪律

```
data/raw/
  manifest.json                  生成参数与逐文件 sha256（只登记 profile_id，不含阈值数值）
  SYN-LJ3/round-01.csv … round-08.csv
  SYN-ZHDQ/round-01.csv … round-20.csv
  SYN-YYCG/round-01.csv … round-30.csv
data/truth/
  SYN-LJ3.truth.csv（0 事件，只有表头）
  SYN-ZHDQ.truth.csv
  SYN-YYCG.truth.csv
```

- 观测 CSV 表头固定 8 列：`round_index,observed_on,point_code,item_code,cumulative_value,unit,missing,raw_text`
- **真值与数据同名不同目录**：`data/raw/<site>/…` 与 `data/truth/<site>.truth.csv` 一一对应。
  `data/README §三` 原文写"同目录同名"，与 `04 §2.2`、`04 §三`、`HANDOFF §二.3` 的 `data/truth/` 布局冲突，
  M1 按多数口径统一为"同名不同目录"，变更见 `06 §五`。
- 逐字节冻结：CSV 与 manifest 全部 LF、UTF-8（无 BOM）、末尾单换行；禁止手改。
  58 个轮次文件 + 3 个真值文件 + 1 个 manifest = **62 个产物**。
- manifest 记的是生成身份（seed、profile_id、每站轮次/测点/行数/事件数、每文件 sha256 与字节数、复现命令），
  **不记控制值也不记速率窗口天数**：窗口属站点配置（`06 D07`），写进数据面就等着被当成规范值引用。
- 复现命令（轮次由档案决定，不传 `--rounds`）：

```bash
python -X utf8 -m pmc synth --seed 20260107 --sites 3 --force
python -X utf8 -m pmc synth --check
git status --porcelain          # 必须为空
```

- 建档（导入的前置）：`synth` 带 `--db` 时把工程 3 / 工况 9 / 测点 588 / 轮次 58 写进台账，
  **不写任何控制值数值**（`design_*` 全空、`threshold_source_kind='none'`），运行时判定的数值仍只能来自用户录入或 M3 核对后的规则集。

- 改生成器 = 必须整目录重新生成并一并提交，`tests/test_synth_freeze.py` 会用固定 seed 重跑一遍并与仓内产物逐字节对账。
