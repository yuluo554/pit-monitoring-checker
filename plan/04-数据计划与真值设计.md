# 04 · 数据计划与真值设计

> 版本：v1（2026-10-07，M0）
> 数据是本题的核心资产：**没有带真值的监测时序，"判读是否不漏不误"就无法自证**。
> 外部依据的查证记录与假数据白名单在 `data/README.md`（不重复登记）；本文件管"要造什么、怎么保证可复现"。

## 二、合成数据设计（M1 落地）

### 2.1 形态学

每条正常序列按基坑变形的三阶段形态生成，而不是随机游走（否则植入的"速率突增"在噪声里无法定义）：

| 段 | 形态 | 物理含义 |
|---|---|---|
| 开挖影响段 | 单调增长 + 与工况深度相关的斜率 | 支护受荷后的主变形 |
| 回弹段 | 反向缓变（坑底隆起、立柱回弹类项目） | 卸载与回弹 |
| 流变段 | 渐近收敛的缓变 | 时间效应 |

叠加项：仪器分辨率（按单位量化到 0.1 mm / 1 kN）、观测时刻抖动、季节性缓变。
**三座虚拟基坑**（虚构名，白名单形式见 `data/README.md` §三）：

| 基坑 | 特征 | 覆盖的监测项目 | 目的 |
|---|---|---|---|
| `SYN·临江路地块 3 号基坑` | 8 轮×日报，无异常 | 全部 14 项 | 误报率的分母 |
| `SYN·中环广场东区基坑` | 7 类异常各植入 ≥ 1 起 | 位移类 + 轴力 + 水位 | 召回率与首超定位误差 |
| `SYN·综合医院地下车库基坑` | 报警未处置跨 3 轮 + 工况变更 + 漏测 | 位移类 + 管线 | 未闭环延续与模块 3 检核 |

### 2.2 事件植入与真值

`event_type ∈ {step, rate_burst, drift, missing, outlier, unit_error, duplicate_report}`
真值列（`data/truth/<site>.truth.csv`，与数据文件同目录同名）：

```
event_id, point_id, round_index, event_type, injected_magnitude, expected_first_alarm_round
```

- `expected_first_alarm_round` 是**理论上首个应触发报警的轮次**，由生成器按植入量与当时生效阈值反算，不是"植入轮次"的复制；
- 阈值待核对阶段，反算用夹具阈值（只进 `tests/fixtures/`），真值文件里的期望值与夹具档位绑定并在 `data/golden/` 登记；
- 每起事件同时记录"除主期望外还应成立的结论"（`also_expect`），评测按"全部非 pass 集合"对账，避免漏报被算成正确；
- 互斥坑当场登记：同一测点同一轮次不得同时植入 `missing` 与 `step`；`unit_error` 植入后该轮不参与速率计算。

### 2.3 导入器要能拒收

`unit_error` 与 `duplicate_report` 两类植入是**给导入器出的考题**：前者必须被单位一致性校验拦下并写进回执，后者必须进修订链而不是覆盖。基准的"漏报清单"里如果这两类被判成引擎漏报，说明拒收通路坏了。

## 三、确定性生成纪律（跨机器复现的根）

| 禁 | 用 | 原因 |
|---|---|---|
| `stdlib random` | `pmc.synth.rng.DetRng`（splitmix64 + stream 派生） | `random` 不承诺跨解释器版本序列一致 |
| `set`/`dict` 迭代序参与输出 | 显式 `sorted()` | 哈希种子导致顺序漂移 |
| 系统时钟进产物 | 落盘文件不带时间戳 | 两次构建必须逐字节一致 |
| 浮点格式化依赖平台 | 固定小数位格式化（按项目单位精度） | 平台 repr 差异 |

产物面：`data/raw/*.csv`、`data/truth/*.truth.csv`、`data/golden/*` 全部**字节冻结入仓**（禁止手改；改生成器就用固定 seed 命令整目录重新生成并提交），配"再生成位级一致"守门测试。

复现命令（M1 起可用）：

```bash
python -X utf8 -m pmc synth --seed 20260107 --sites 3 --rounds 8 --force
python -X utf8 -m pmc synth --check          # 与仓内冻结产物逐字节对账
git status --porcelain                       # 必须为空
```

## 四、评测期望与门槛（M4）

| 指标 | 定义 | 门槛 | 四态归类 |
|---|---|---|---|
| 报警召回率 | 命中 `expected_first_alarm_round` 的事件 / 应报警事件总数 | ≥ 0.95 | 分母为 0 → 不可判 |
| 误报率 | 无真值支撑的 alarm 数 / 正常观测轮次数 | = 0 | 同上 |
| 首超轮次定位误差 | `|检出轮次 − 期望轮次|` 的分布（给中位数与 P95） | 中位 = 0，P95 ≤ 1 | 同上 |
| 未闭环延续率 | 报警后未处置的测点在后续轮次仍带 `unclosed` 的比例 | = 1 | 通路未通 → 不可用 |
| 待定值不出货 | 输出结论的行里 `threshold_source_kind = none` 的条数 | = 0 | 常驻断言（DDL CHECK 兜底） |
| 导入回执完备率 | `rows_accepted + rows_rejected = rows_total` 的批次比例 | = 1 | 同上 |

`bench --markdown` 生成指标表；README 指标节由该表逐行对账（`test_readme_honesty.py` 现在就在守这条）。

## 五、数据台账新增登记要求

任何新入仓的数据文件（含 M1 的合成目录、M4 的 golden）都必须在 `data/README.md` 的台账表加一行：来源（程序生成 / 渠道）、许可或版权处置、`status`、备注。
二进制样例（未来的 xlsx 报告样例）走"白名单 + sha256 与台账联动"通路：新二进制入仓 = 白名单与台账同步更新，否则脱敏审计失败。

## 六、里程碑依赖

```
M1 数据先行（生成器 + 导入器 + 真值） ──► M2 判定内核 ──► M4 基准
        │                                   ▲
        └─► M3 条款核对（把 pending 转 verified，规则数值写入）
```

**条款核对与算法开发解耦**：M2 不等 M3。用测点档案里的设计值（`design_value`）跑通判定与基准，标准回退档在 M3 逐条转 `verified` 后补进规则集 —— 这样"未核对不出货"的通路和"核对了能出货"的通路都会被真实测到。
