## 一、bench 要回答的问题，以及它不回答什么

一句话：**"判定与检核对得上真值吗？"** —— 用仓内自带的 11 起事件真值当考卷，跑一遍完整通路（建档→导入→判定），
逐起对账并出四态指标。这是引擎退化的护栏，也是 README 指标节里基准行的唯一数值来源。

**它不是**：对"已核对规范"的精度声明。基准的标尺是**合成自证档位**（`pmc/synth/profile.py`，
`PROFILE_ID = syn-fixture-grade-1`），它由生成器与真值同源反算，所以"合成面全对"在逻辑上不能读作
"符合 GB 50497-2019"。因此：**README 指标节的基准四行永远写「不可用/不可判」，合成面的实测数值放在另一节并标明平面**
（禁项一 / 口径 C11 / `test_readme_honesty.py`）。

### 1.1 档位来源（P08 结论，见 `06 D41`）

`bench` 是产品命令：onedir exe 里没有 `tests/`，所以判定夹具（`tests/fixtures/`）不能当基准的输入。三条路里选第一条：

## 二、装配顺序（`pmc bench` 一次运行做的事）

全部在 `sqlite3.connect(":memory:")` 里进行：**评测不产生任何工作树文件**，写 golden 必须显式 `--write-golden`。

| 步 | 动作 | 复用的既有通路 |
|---|---|---|
| 1 | 定位数据目录、装载字典 / 依据登记表 / 规则集 | `paths.find_data_dir`、`catalog.items`、`contract.clauses`、`rules.loader` |
| 2 | `apply_schema` + `freeze.build(data_dir, seed, 3)` + `seed_ledger` 建三座站档案（不重生成冻结产物） | `synth.freeze`（HANDOFF §四之③：建档走 freeze，不撞 `--force`） |
| 3 | 逐轮 `csvio.load_file → parse_csv → store.write_batch` 导入 `data/raw/<site>/round-NN.csv`，收 58 份回执 | M1 导入器，含被拒收行 |
| 4 | 仅 `--plane synth`：把合成自证档位按 `item_code` 挂进 `point` 档案（`kind=user_input`、`status=verified`、evidence 自述"合成自证档位，非设计文件值、非规范条文值"），并按站档案组内存规则 | `alarm.engine.archive_threshold` 的第一档 |
| 5 | `engine.run_check(write=True)` 逐站整段重算并落 `alarm_state` | M2 判定内核，一行不重实现 |
| 6 | 从**落库后**的 `alarm_state / observation / import_batch` 读数并对账（不是从内存 DTO），再算指标 | C16：判定与评测都只认链上最新行 |
| 7 | `--plane synth` 默认与 `data/golden/bench_synth.json` 位级对账 | §八 |

第 4 步为什么写 `user_input`：阈值来源只有三档（`design_value / standard_value / user_input`，C2），
合成档位既不是设计文件也不是规范条文，`user_input` + 自述 evidence 是唯一不冒充任何一者的登记方式（与 M2 夹具同一手法）。

### 2.1 两个评测面（`--plane`）

| 平面 | 词 | 阈值来源 | 用途 |
|---|---|---|---|
| 合成自证档位面 | `synth`（缺省） | `pmc/synth/profile.py` 挂进档案 | 引擎回归护栏，出数值 |
| 台账面 | `ledger` | 只用台账现有来源（生产数据面 = 全待定值） | 反证"依据没核对就不出货"，指标不可用 |

## 三、四态指标口径（分子 / 分母 / 边界 / 门槛）

状态词只有四个（`METRIC_STATES`）：`达标 / 未达标 / 不可判 / 不可用`。
归类次序：**通路未通 → 不可用**；分母为 0 → 不可判；门槛不满足 → 未达标；否则达标。

真值支撑集（下面两条指标都靠它）：对每一起 `expected_first_alarm_round = E` 非空的事件，
该 `(工程, 测点, 项目)` 上**轮次 ≥ E** 的判定行是"真值允许的报警行"；其余判定行是"真值说该轮不许报警"的行。

| 码 | 指标名（README 用词） | 分子 | 分母 | 门槛 | 边界 |
|---|---|---|---|---|---|
| `recall` | 报警召回率 | 期望轮次非空且**检出到报警**（首条未闭环行存在）的事件数 | 期望轮次非空的事件数 | ≥ 0.95 | 通路未通→不可用；分母 0→不可判 |
| `false_alarm` | 误报率 | 不在支撑集内却处于 `UNCLOSED_STATES` 的判定行数 | 不在支撑集内的判定行数（=「正常观测轮次数」） | = 0 | 同上；分母 0→不可判 |
| `location_error` | 首超报警轮次定位误差 | — | — | 中位 = 0 且 P95 ≤ 1 | 通路未通→不可用；**检出集为空**→不可判 |
| `missed_list` | 漏报清单 | 期望轮次非空却**没有**任何未闭环行的事件数 | 同 `recall` 分母 | = 0 起 | 通路未通→不可用；分母 0→不可判 |
| `unclosed_carry` | 未闭环跨轮次延续 | 相邻两行里前一行未闭环且后一行仍带未闭环的对数 | 前一行未闭环的相邻对数 | = 1 | 通路未通→不可用；分母 0→不可判 |
| `undetermined_blank` | 待定值阈值列脱空 | 出货行（状态非 undetermined）里 `threshold_source_kind = none` 的条数 | 出货行数 | = 0 条 | 常驻断言：分母为 0 时记「达标（无出货行）」 |
| `receipt_balance` | 导入回执完备率 | 回执里 `accepted + rejected = total` 成立的批次数 | `import_batch` 批次数 | = 1 | 批次 0→不可判 |

定位误差的分布只取**已检出**事件（晚报/早报都在内，漏报另计），误差不取绝对值的符号写进逐起表：- `误差 = 检出首超轮次 − 期望轮次`（正 = 晚报 N 轮，负 = 早报 N 轮，0 = 命中）；
- 中位数：排序后奇数取中间项，偶数取中间两项算术平均；
- P95：**最近秩法**（`ceil(0.95 × n)` 位置的实测值，不做插值），`n < 20` 时在说明列如实标注样本量，不假装有分布；
- 附带报告「严格首超命中率」（`误差 = 0` 的事件占已检出事件的比例）——它比"召回"更硬，但不设独立门槛，
  以免凭空造出 `04 §四` 没有的第二把尺。

**晚报/早报的归属**：晚报不算误报（该行在支撑集内），但计入定位误差与逐起表；
早报既计入误差（负号）又计入误报分子（该轮真值说不许报警）。漏报只有一条定义：期望轮次非空且一站未闭环行都没有。

### 3.1 门槛字面（`GATE_TEXT`，代码与文档逐字对齐）

`≥0.95`（召回）/ `=0`（误报）/ `中位=0 且 P95≤1`（定位误差）/ `=0 起`（漏报清单）/
`=1`（未闭环跨轮次延续）/ `=0 条`（待定值阈值列脱空）/ `=1`（导入回执完备率）。

### 3.2 合成面的档位凭证字面（`GRADE_EVIDENCE`）

`SYNTH-GRADE:syn-fixture-grade-1（合成自证档位：非设计文件值、非规范条文值）`
——写进内存台账的 `point.threshold_evidence` 与规则的 `window_source.evidence`，
自述它不是什么；凭证串本身也不得进 `data/`（`test_m4_discipline.py` 与 `test_m4_bench.py` 各钉一道）。

## 四、`also_expect` token 的对账语义（真值 7 列不改，C12）

`07 §6.1` 的 10 个 token 白名单逐个落地；出现白名单外的 token → `InputError`，**先登记再使用**。
检查项名（`CHECK_*`）就是输出表里"对账项"的取值：

| token | 检查项名 | pass 条件（从落库行读） | 类型 |
|---|---|---|---|
| `alarm_basis=cumulative` | `触发依据` | 首条未闭环行的 `trigger_basis == cumulative` | 判定依赖 |
| `alarm_basis=rate` | `触发依据` | 同上 `== rate` | 判定依赖 |
| `alarm_basis=both` | `触发依据` | 同上 `== both` | 判定依赖 |
| `unclosed>=N` | `未闭环延续` | 该 `(测点,项目)` 上轮次 ≥ 首超轮的未闭环行数 ≥ N | 判定依赖 |
| `no_alarm` | `无报警` | 该 `(测点,项目)` 上不存在任何未闭环行 | 判定依赖 |
| `no_row` | `该轮不出判定行` | `(测点, 植入轮)` 上没有 `alarm_state` 行 | 判定依赖 |
| `no_interpolation` | `缺测不补值` | `(测点, 植入轮)` 的链上最新行 `missing = 1` 且 `value_cum IS NULL` | 导入层 |
| `reject=unit_mismatch` | `单位不一致被拒收` | 该轮回执里有一条 `reason_code = unit_mismatch` 且 `detail` 指向该测点，且该 `(测点,轮)` 无观测行 | 导入层 |
| `import_revision=2` | `修订链长度` | `(测点, 植入轮)` 的 `revision_seq` 集合 `== [1, 2]`，链头为 seq=2（`superseded_by IS NULL`） | 导入层 |
| `persist_exact` | `落盘数值不变` | 链上最新行的 `value_cum` 与轮次 CSV 该测点 `cumulative_value` 字面**逐位相等**（不四舍五入、不清洗） | 导入层 |

事件结论词（`OUTCOME_*`，逐起表"结论"列的全部取值）：
`命中`（有期望轮且误差 = 0）/ `晚报`（误差 > 0）/ `早报`（误差 < 0）/ `漏报`（有期望轮而无未闭环行）/
`无报警符合`（无期望轮且全部可评检查项 pass）/ `考题失败`（无期望轮而有检查项 fail）/
`不可判`（通路未通，或该事件带判定依赖检查项而该面无出货行）。

## 五、两类"导入器考题"怎么算 pass（`04 §2.3`）

`unit_error` 与 `duplicate_report` 是给**导入器与修订链**出的题，不是给报警引擎出的题：

- `unit_error`（`SYN-ZHDQ-E05`）：pass = 该 `(测点,轮)` 无观测行 + 无判定行 + 该轮回执有一条 `unit_mismatch`。
  它**没有** `expected_first_alarm_round`，所以**不进召回分母**，也**绝不进漏报清单**——它若出现在漏报清单里，
  说明评测把"该轮根本没进台账"读成了"引擎漏报"，`test_m4_bench.py` 有反向断言钉住这一点。
- `duplicate_report`（`SYN-ZHDQ-E03`）：pass = 修订链 `[1,2]` 且链头 seq=2 + 判定按修正值（26.0）出报警 +
  `alarm_basis=both`。这条**两边都考**：修订链属导入器，按链头取值属引擎（C16），所以它既在逐起表里对账，
  也允许因引擎取错链而行失败——那时它是判定失败，不是导入失败。
- `missing` 与 `outlier` 同属"无报警期望"组：`missing` 考导入器不补值，`outlier` 考引擎不被单点粗差骗报警。

**结论表的分列**：`BENCH_MISSES` 只列 `missed_list` 定义的漏报；`BENCH_GUARDS` 列导入层检查项的失败；
两列永不相交（`test_m4_bench.py::test_import_guard_events_never_appear_in_the_miss_list`）。

## 六、`pmc bench` 输出契约

参数：`--plane synth|ledger`（缺省 synth）、`--sites CODE[,CODE…]`、`--all`（等价缺省全三座，

### 6.1 `--json` 字段契约（`schema = pmc-bench/1`）

```
schema, plane, grade_profile, seed, sites[], data_dir,
truth{sha256{site:hex}, events, alarm_expectant, no_alarm_expectant},
counts{batches, judged_rows, judgeable_rows, undetermined_rows, import_rejected_rows},
```

`checks[].ok` 三态：`true / false / null`（null = 该面无出货行，判不了）。

### 6.2 `--markdown` 列序（与 README 指标节同列序，可直接替换）

`| 指标 | 状态 | 说明 | 复现命令 |`，行序 = §三 表序（召回 → 误报 → 定位 → 漏报清单 → 未闭环 → 待定值 → 回执）。
说明列单行、不含竖线；复现列：漏报清单写 `` `python -m pmc bench --json` ``，其余写 `` `python -m pmc bench` ``。
README 的 指标节基准行取 `--plane ledger` 的输出，合成面整表落 in README 的 基准评测节，两处都由
`test_m4_bench.py` 与实跑逐行对账（不是"照抄一遍"）。

## 七、退出码（C4 的 bench 轴）

| 码 | 触发集合 |
|---|---|
| 0 | 参与统计的每一项指标都是「达标」，且 golden 位级一致 |
| 1 | 有降级项，任一即触发：存在漏报 / 任一指标不可判或不可用 / 任一指标未达标 / 导入层检查项失败 / 依据一条都没核对（`ledger` 面必然触发） |
| 2 | 输入不可用：数据目录或真值缺失、真值表头不是 7 列、token 未登记、轮次 CSV 缺失、台账装配失败 |

`BENCH_NOTES` 的固定原因码（`NOTE_*`，共 9 码，新增先登记）：
`plane_is_synthetic`（本面标尺是合成自证档位，不构成规范精度声明）、
`clauses_unverified`（依据登记表可供货条款 0 条）、
`no_shippable_conclusion`（出货行 0 条：通路未通，指标记不可用而不是 0 分）、
`small_sample_p95`（定位误差样本 < 20 起，P95 用最近秩实测值不插值）、
`truth_shrunk`（golden 里有而本轮没有的事件：真值面缩水）、
`golden_missing`、`golden_written`（`--write-golden` 重基线已落盘）、
`golden_drift`、`subset_skips_aggregate_golden`（`--sites` 子集只比对站点段，聚合指标不比对）。

## 八、`data/golden/bench_synth.json`（评测期望结果，C19 里"M4 创建"的那一项）

- `schema = pmc-golden-1`（`test_data_discipline.py` 要求顶层键以 `pmc-` 开头且带 `notice`）；
- 内容：平面、`grade_profile`（**只有 profile_id，没有档位数值**）、seed、sites、三站真值 sha256、
  逐起事件对账结果、七项指标的 state/分子/分母/value_text、装配计数；

- 位级一致：报告字节 = `json.dumps(..., ensure_ascii=False, indent=2, sort_keys=True) + "\n"`（LF）；

- `--sites` 取子集时只比对 golden 里对应站点的那一段，`--plane ledger` 不与 golden 比对（`golden.state = skipped`）；
- 新增数据文件即 `data/README §五` 台账加一行（`plan/04 §五`）。

| 4 | `python -X utf8 -m pmc bench --all --json`（合成面） | 0 |
| 5 | `python -X utf8 -m pmc bench --plane ledger`（反证环：依据没核对就不出货） | 1 |

第 5 环是**期望 1** 的反证，不是失败：`HANDOFF §二.4` 把"依据未核对"列为 bench 的降级触发项，
而生产数据面一条依据都没核对（禁项一），于是缺省面与反证面必然给出不同退出码。
链的口径因此定为："**合成面达标 = 0；台账面不出货 = 1**"，两环都跑才能同时锁住"引擎没退化"和"没在幻觉数值上出货"。
这一条是本轮唯一对 `HANDOFF §二.6` 的重新解释，已写进 `05 §三之五` 偏差表第 6 行与 `06 D41`。
